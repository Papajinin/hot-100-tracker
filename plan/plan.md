# Hot 100 Tracker 기획안

> 개인 앱 (가족 AIN 앱이 아님). 매주 엑셀로 손수 정리하던 빌보드 HOT 100 기록을 자동으로 (2026-11-02 시작)

## 하는 일
- 매주 GitHub(Actions)가 빌보드 HOT 100을 읽어서 `data/state.json`을 고쳐 둔다. 앱은 그 파일을 보여 주기만 한다 (로그인·Firebase 없음)
- 시간: 한국 **수·목·금 아침 9시, 오후 3시** (UTC 수·목·금 0시, 6시). 이미 넣은 주면 그냥 끝남 (나머지는 놓쳤을 때 대비). GitHub 예약은 몇 시간 늦게 돌기도 함
- 한 주를 놓쳐도 다음 번에 **빠진 주부터 차례로** 채움 (빌보드 지난 차트 주소: `/charts/hot-100/YYYY-MM-DD/`)
- 화면 모양이 바뀌어 못 읽으면 실패 → GitHub가 메일로 알려 줌

## 기록 규칙 (사용자가 엑셀로 하던 방식)
- **한 번이라도 Top 10에 든 곡만** 기록. 처음 Top 10에 든 순서대로 목록 끝에 추가
- 매주: Top 10이면 **Top10 횟수 +1**. **주(WKS)**는 빌보드 "Weeks on Chart" 숫자 그대로 (작년까지 포함)
- Top10 횟수는 처음 Top 10에 든 때부터 해를 넘어 계속 셈
- **올해의 곡** (파랑, 조건을 넘은 순서로 번호): Top10 1번+30주 / 2번+20주 / 3번+10주 / 4번 이상+4주
  - 올해의 곡은 차트에서 빠져도 목록에 그대로
- **차트 아웃** (빨강, 엑셀에서는 숨김): 올해의 곡이 되기 전에 차트에서 빠진 곡
  - 나중에 **Top 10으로 다시 들어오면 살림**. 11~100위로만 돌아오면 그대로 탈락 (2026-11-02)
- **"-" 곡** = 작년에서 넘어온 곡. 횟수는 세지만 올해의 곡 번호는 붙이지 않음. 차트에서 빠지면 탈락

## 해가 바뀔 때
- **12월 날짜 차트까지만** 기록하고 멈춤 (연말엔 캐롤이 차트를 채워서 데이터가 오염됨)
- 1월 날짜 차트는 기록하지 않음. 그동안 앱은 그해 최종 목록을 보여 줌
- 사용자가 **1월 2주차쯤 새해 엑셀**을 주면 그걸로 `data/state.json`을 새로 만듦 (지난해 기록은 GitHub 예전 버전에 남음). 엑셀의 마지막 주 다음 주부터 다시 자동
- 어떤 곡을 "-"로 넘길지는 사용자가 새해 엑셀에서 직접 정함

## 파일
| 파일 | 하는 일 |
|---|---|
| `index.html`, `style.css`, `app.js` | 화면 (2026 테마: 검정 + 민트) (탭: 지켜보는 중 / 올해의 곡 / 차트 아웃, 이번 주 바뀐 것. 왼쪽에 올해의 곡 번호, 순위는 가수 앞에 "지난주→이번 주"(7→4위, NEW→4위, RE→4위), 줄을 누르면 잘린 제목·가수 펼쳐 보기. 차트 아웃 탭은 "지금 39→34위" 또는 "마지막 23위 · 10/24주", 빠진 올해의 곡은 "차트 아웃 · 마지막 23위") |
| `data/state.json` | 기록 전체 (GitHub가 매주 고침). 첫 자료는 사용자 엑셀 (10/31주까지) |
| `tools/chart.mjs` | 빌보드 화면 읽기 + 규칙 |
| `tools/update.mjs` | 다음 주 차트 읽어서 넣기 (`node tools/update.mjs`) |
| `tools/test.mjs` | 규칙 테스트 (`node tools/test.mjs`). GitHub도 매주 먼저 돌림 |
| `.github/workflows/weekly.yml` | 예약 작업 |

## state.json 곡 하나
`{ title, artist, top10, wks, rank(이번 주 순위, 없으면 null), lw(지난주 순위 숫자·NEW·RE), lastRank·lastWeek(차트에서 빠지기 전 마지막 순위와 그 주), debut(처음 차트인 날짜), status, no }`
- 탈락(out) 곡도 HOT 100 안에 있으면 rank·lw는 적음 (횟수는 안 셈)
- status: `watch` 판정 전 · `song` 올해의 곡(no 번호) · `carry` "-" 곡 · `out` 탈락(`before`에 탈락 전 상태)
